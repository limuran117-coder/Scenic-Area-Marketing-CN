### 核心设计（Week 4 新增）

**LLM Query Translator 3-Stage Chain：**
- Stage 1: QueryIntentClassification（METRIC_RANKING / METRIC_TREND / CONTENT_ANALYSIS 等 9 类）
- Stage 2: EntityExtraction（scenic_spot_ids / metric_types / date_range / filters）
- Stage 3: QueryGeneration（→ Function Call 或 SQL）
- D-026：3-Stage 优于单次 prompt（避免 schema 截断）
- D-027：优先返回 FunctionCall 而非 SQL（Agent 可解释性）
- D-028：fail gracefully 策略

**QueryIntent → Function Call 映射（D-031）：**
- METRIC_RANKING → aggregateWeeklyMetrics（F-011）
- METRIC_TREND → calculateSearchTrend（F-001）
- CONTENT_ANALYSIS → enrichContentAsset（F-010）
- ALERT_REVIEW → detectAnomaly（F-009）
- INSIGHT_SUMMARY → generateDailyInsight（F-008）

**AgentContextInjection：**
- D-030：Session 启动仅注入约2KB 简化 Schema（Object Types + Functions 列表）
- 不注入完整 100KB ontology.json（Token 限制）

**Agent Write Path（D-029）：**
- 所有 Agent 写操作必须经 ActionDispatcher
- 禁止直接调用 send_feishu_card.py（必须走 Action 治理）
- LOW_STAKES: 直接执行；MEDIUM_STAKES: 执行后通知；HIGH_STAKES: 执行前必须批准

### 技术研究

**Palantir AIP Ontology 最新动态（web search）：**
- 第三代 Ontology = 可执行知识网络（Function + Action 内置）
- 关键区分：知识图谱描述"哪里有什么"，Ontology 还能"自动规划+控制执行"
- Palantir Copilot = 自然语言查 Ontology（对标我们的 AgentQueryHandler.ask()）
- OAG（Ontology-Augmented Generation）= LLM + 企业专属数据 + 业务逻辑融合

**Text-to-SQL 现状：**
- 当前主流方案：2-Stage LLM（schema selection → SQL generation）
- PET-SQL 框架（2024）：参考列选择 + 一致性解码
- 我们的 QueryTranslator 借鉴其思路但面向 Function Call 而非纯 SQL
