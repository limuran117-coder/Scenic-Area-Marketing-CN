# SOP质量升级建议 — 来自agent-skills的对照分析

> 参考：addyosmani/agent-skills（40K⭐），对比日期：2026-05-24

---

## 一、核心差距：3个结构性缺失

agent-skills每个技能通用的7层结构 vs 我们SOP平均3层：

| 维度 | agent-skills | 我们当前SOP | 缺失影响 |
|:-----|:------------|:-----------:|:--------|
| ① YAML元信息 | `name/description` + Use when触发条件 | ❌ 大部分没有 | cron session无法自动匹配技能 |
| ② When to Use / When NOT | ✅ 明确触发例+非触发例 | ❌ 几乎全无 | isolated session容易在不该执行时执行 |
| ③ Common Rationalizations | ✅ 预判常见借口并反驳 | ❌ 全无 | 坏习惯反复出现 |
| ④ Red Flags | ✅ 什么情况=出问题了 | ❌ 少数有 | 异常不能及时发现 |
| ⑤ Verification | ✅ 执行后检查清单 | ❌ 少数有 | 输出质量参差 |
| ⑥ 分层输出 | 先Overview → 再Steps → 最后Checkpoints | ⚠️ 步骤混合JSON模板 | 模板混在流程中，难以单独维护 |
| ⑦ Meta技能 | `using-agent-skills` 任务路由树 | ❌ 仅daily-tasks.md列表 | 无按场景的skill发现机制 |

## 二、升级优先级（分3批）

### 🔴 第1批：核心SOP（本周可做）

以下SOP每天执行，影响最大，优先加3个缺失结构：

| SOP | 缺失 | 建议操作 |
|:----|:----|:--------|
| `抖音指数日报` | 缺YAML/When/RedFlag/Verify | 加front matter + 采集失败判断 + 输出检查清单 |
| `每日复盘整合` | 缺When/RedFlag/Verify | 加判断层 + 复盘质量检查 |
| `竞品内容动态` | 缺YAML/When/RedFlag | 加触发条件 + 数据异常的red flag |
| `竞品爆款拆解` | 缺Verify/RedFlag | 加拆解质量检查 |

### 🟡 第2批：运维SOP（本周）

| SOP | 缺失 | 建议操作 |

## 三、标准化模板（直接套用）

### 所有SOP的新Header

```markdown
---
name: sop-抖音指数日报
description: 采集电影小镇及7个竞品在抖音创作者平台的指数数据。Use when 每日10:30前，当抖音指数日报需要生成时。Do NOT use when CDP浏览器离线或Cookie失效（此时应报告失败而非降级输出历史数据）。
---

# 抖音指数日报 SOP

> 采集+分析+发送全部流程 | 脚本：douyin_index_v9.py | 每日10:30
```

### 新增：Common Rationalizations

```markdown
## 常见错误（Common Rationalizations）

| 常见的想法 | 事实 |
|:---------|:-----|
| "先发出去，数据少点没关系" | ❌ 缺失数据=误导决策，宁缺毋滥 |
| "上次的数据和今天差不多" | ❌ 景区指数日波动可达±30%，昨天数据毫无意义 |
| "这里加一句废话不会有人注意" | ❌ 每条内容都会被放大检视 |
| "来不及了先发，后面补" | ❌ 飞书卡片不能撤回，发了就是最终版 |
```

### 新增：Red Flags

```markdown
## 红色警报（Red Flags）

- 🔴 采集脚本返回空列表 → 立即停止，报告Cookie失效
- 🔴 连续3天搜索指数零增长 → 采集站可能已改版
- 🔴 8个景区中超过2个无数据 → 降级不可用，报告失败
- 🔴 环比变化超过±100% → 需要人工确认数据准确性
```

### 新增：Verification

```markdown
## 输出检查（Verification）

发送前确认：
- [ ] 8个景区数据齐全，无空白单元格
- [ ] 电影小镇行已加粗 🔺标注
- [ ] 涨跌方向与实际数据一致
- [ ] 深度分析至少3条，非泛泛而谈
- [ ] 判断层包含3个必要分项（影响等级/建议动作/执行窗口）
- [ ] 表格和文本之间无多余空行
- [ ] 数据来源和采集时间已标注
```

## 四、附加建议：创建"SOP路由树"

类似agent-skills的 `using-agent-skills` 元技能，写一个**SOP查询表**：

```
任务来了
  │
  ├── 需要采集数据？    → 抖音指数日报 / 小红书日报
  ├── 需要分析竞品？    → 竞品关键词深度分析 / 竞品爆款拆解
  ├── 需要监控动态？    → 竞品内容动态 / 文旅热点追踪
  ├── 每天结束时？      → 每日复盘整合
  ├── 系统出问题了？    → 系统健康检查 / 专属浏览器维护
  └── 不知道执行什么？  → 每日任务总览
```

当前 `每日任务总览` 已有类似功能但过于扁平（纯表格），改成决策树更直观。

## 五、手动执行项

⚠️ **这些不需要写入SOP，是我改造时需注意的原则：**

1. **SOP和JSON模板分离** — 当前多个SOP中混写了卡片JSON（抖音日报/复盘等），应把JSON模板放 `wiki/技术配置/飞书卡片模板.md`，SOP只描述流程
2. **"When NOT to Use" 是重要的安全网** — isolated cron session没有人类判断，必须先说清楚什么情况下不执行
3. **Red Flag 要有数字阀值** — 不要写"数据异常"，要写"环比>±100%"或"连续3天无变化"
