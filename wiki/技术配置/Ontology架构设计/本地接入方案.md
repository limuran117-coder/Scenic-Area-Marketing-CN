## 二、存储层：Ontology Store（SQLite + JSON 双轨）

### 2.1 为什么选 SQLite

| 选项 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **SQLite** | 零配置、本地、Python内置、支持JSON查询 | 不适合超大数据集 | ✅ 选定 |
| Neo4j | 图查询强大 | 需装服务端、太重 | ❌ |
| 纯JSON文件 | 最简单 | 查询需全量读取、无索引 | ⏳ Phase 1过渡用 |
| DuckDB | OLAP查询快 | 写频繁场景差 | ❌ |

### 2.2 双轨策略

```
Phase 1 (Now):  JSON 文件 → 适配器输出验证
Phase 2 (本周): JSON → SQLite 导入 → 建立核心 Store
Phase 3 (下周): SQLite → 日常读写 · JSON 仅做 Git 快照
```

### 2.3 SQLite Schema 设计

```sql
-- ontology_store.db

-- ==========================================
-- 1. 对象表（核心数据）
-- ==========================================

-- 景区实体
CREATE TABLE scenic_spots (
    id          TEXT PRIMARY KEY,       -- ss_<name>
    name        TEXT NOT NULL,
    category    TEXT,                   -- 主题乐园/古镇/自然景观/…
    province    TEXT,
    city        TEXT,
    competitors TEXT,                   -- JSON array of scenic_spot ids
    tags        TEXT,                   -- JSON array
    created_at  TEXT DEFAULT (datetime('now')),
    updated_at  TEXT DEFAULT (datetime('now'))
);

-- 指标快照（核心写入表——每天插入新行）
CREATE TABLE metric_snapshots (
    id             TEXT PRIMARY KEY,    -- ms_<source>_<date>_<景区>
    spot_id        TEXT NOT NULL REFERENCES scenic_spots(id),
    source         TEXT NOT NULL,       -- douyin / xiaohongshu / visitors / baidu
    date           TEXT NOT NULL,       -- YYYY-MM-DD
    metric_type    TEXT NOT NULL,       -- search_index / comprehensive_index / visitor_count / …
    value          REAL NOT NULL,
    daily_change   REAL,               -- 日环比（%）
    confidence     REAL DEFAULT 0.5,   -- 0.0-1.0
    raw_data       TEXT,               -- JSON: 原始数据备份
    ingested_at    TEXT DEFAULT (datetime('now'))
);
CREATE INDEX idx_ms_spot_date ON metric_snapshots(spot_id, date);
CREATE INDEX idx_ms_source_date ON metric_snapshots(source, date);

-- 内容资产（小红书笔记、抖音视频等）
CREATE TABLE content_assets (
    id             TEXT PRIMARY KEY,    -- ca_<source>_<id>
    source         TEXT NOT NULL,       -- xiaohongshu / douyin / weibo
    external_id    TEXT,                -- 平台原始ID
    spot_id        TEXT REFERENCES scenic_spots(id),  -- 关联景区（可为空）
    title          TEXT,
    description    TEXT,
    url            TEXT,
    author         TEXT,
    like_count     INTEGER DEFAULT 0,
    comment_count  INTEGER DEFAULT 0,
    share_count    INTEGER DEFAULT 0,
    publish_date   TEXT,
    content_type   TEXT,               -- video / note / article
    tags           TEXT,               -- JSON array
    raw_data       TEXT,               -- 原始数据备份
    ingested_at    TEXT DEFAULT (datetime('now'))
);
CREATE INDEX idx_ca_spot ON content_assets(spot_id);
CREATE INDEX idx_ca_source ON content_assets(source);
CREATE INDEX idx_ca_date ON content_assets(publish_date);

-- 事件/动态（竞品活动、行业趋势、政策）
CREATE TABLE events (
    id             TEXT PRIMARY KEY,    -- ev_<type>_<date>_<seq>
    type           TEXT NOT NULL,       -- competitor_activity / industry_trend / policy_change / sentiment_incident
    title          TEXT NOT NULL,
    description    TEXT,
    severity       TEXT DEFAULT 'low',  -- low / medium / high / critical
    date           TEXT NOT NULL,
    related_spots  TEXT,                -- JSON array of spot_ids
    source_url     TEXT,
    raw_data       TEXT,
    ingested_at    TEXT DEFAULT (datetime('now'))
);
CREATE INDEX idx_events_date ON events(date);
CREATE INDEX idx_events_type ON events(type);

-- 营销活动
CREATE TABLE marketing_campaigns (
    id             TEXT PRIMARY KEY,    -- mc_<name>
    name           TEXT NOT NULL,
    spot_id        TEXT REFERENCES scenic_spots(id),
    start_date     TEXT,
    end_date       TEXT,
    budget         REAL,
    channels       TEXT,                -- JSON array
    kpis           TEXT,                -- JSON: {"visitors": 1000, "revenue": 50000}
    status         TEXT DEFAULT 'planned',  -- planned / active / ended / cancelled
    notes          TEXT,
    created_at     TEXT DEFAULT (datetime('now'))
);

-- ==========================================
-- 2. 关系表（Link Types 实例化）
-- ==========================================

-- 景区间关系
CREATE TABLE spot_relations (
    source_id      TEXT NOT NULL REFERENCES scenic_spots(id),
    target_id      TEXT NOT NULL REFERENCES scenic_spots(id),
    relation_type  TEXT NOT NULL,       -- competes_with / located_near / same_category / …
    confidence     REAL DEFAULT 0.8,
    updated_at     TEXT DEFAULT (datetime('now')),
    PRIMARY KEY (source_id, target_id, relation_type)
);

-- 事件-景区关联
CREATE TABLE event_spot_links (
    event_id       TEXT NOT NULL REFERENCES events(id),
    spot_id        TEXT NOT NULL REFERENCES scenic_spots(id),
    relevance      REAL DEFAULT 1.0,   -- 关联度
    PRIMARY KEY (event_id, spot_id)
);

-- ==========================================
-- 3. 审计与元数据
-- ==========================================

-- 接入日志（每次adapter执行记录）
CREATE TABLE ingest_log (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    adapter_name   TEXT NOT NULL,       -- adapter-douyin / adapter-xiaohongshu / …
    status         TEXT NOT NULL,       -- success / partial / failed
    source_file    TEXT,
    records_added  INTEGER DEFAULT 0,
    records_updated INTEGER DEFAULT 0,
    error_message  TEXT,
    started_at     TEXT,
    finished_at    TEXT
);

-- 查询日志（Query Layer 调用记录）
CREATE TABLE query_log (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    query_text     TEXT NOT NULL,
    query_type     TEXT,                -- cross_type / trend / comparison / …
    result_count   INTEGER,
    latency_ms     INTEGER,
    queried_at     TEXT DEFAULT (datetime('now'))
);

-- Action 日志（所有对外发送记录）
CREATE TABLE action_log (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    action_type    TEXT NOT NULL,       -- send_card / create_alert / update_dashboard
    target         TEXT,                -- feishu_group_id / webhook_url
    payload_summary TEXT,
    status         TEXT,                -- queued / sent / failed
    error_message  TEXT,
    created_at     TEXT DEFAULT (datetime('now'))
);

-- ==========================================
-- 4. 视图（常用查询预定义）
-- ==========================================

-- 抖音8景区今日排名视图
CREATE VIEW v_douyin_ranking AS
SELECT s.name AS 景区,
       ms.value AS 搜索指数,
       ms.daily_change AS 搜索日环比,
       (SELECT ms2.value FROM metric_snapshots ms2
        WHERE ms2.spot_id = ms.spot_id AND ms2.date = ms.date
          AND ms2.source = 'douyin' AND ms2.metric_type = 'comprehensive_index'
        LIMIT 1) AS 综合指数,
       (SELECT ms2.daily_change FROM metric_snapshots ms2
        WHERE ms2.spot_id = ms.spot_id AND ms2.date = ms.date
          AND ms2.source = 'douyin' AND ms2.metric_type = 'comprehensive_index'
        LIMIT 1) AS 综合日环比
FROM metric_snapshots ms
JOIN scenic_spots s ON ms.spot_id = s.id
WHERE ms.source = 'douyin'
  AND ms.metric_type = 'search_index'
  AND ms.date = (SELECT MAX(date) FROM metric_snapshots WHERE source = 'douyin')
ORDER BY ms.value DESC;

-- 跨源趋势视图
CREATE VIEW v_weekly_trend AS
SELECT s.name AS 景区,
       ms.metric_type AS 指标,
       ms.date AS 日期,
       ms.value AS 数值,
       ms.source AS 数据源
FROM metric_snapshots ms
JOIN scenic_spots s ON ms.spot_id = s.id
WHERE ms.date >= date('now', '-7 days')
ORDER BY s.name, ms.metric_type, ms.date;
```

```python
class OntologyAdapter(Protocol):
    def ingest(self) -> IngestResult:
        """从源读取 → 映射 → 写入 Store"""
        ...

    def validate(self) -> bool:
        """检查源数据可用性"""
        ...

# 输出结构
@dataclass
class IngestResult:
    status: Literal["success", "partial", "failed"]
    records_added: int
    records_updated: int
    errors: list[str]
```

## 四、查询层：Query Layer

### 4.1 设计目标

```
自然语言 → Query Layer → SQL → Store → 结构化结果 → Report / Agent
```

### 4.2 预定义查询模板（直接调SQL）

```python
class OntologyQuery:
    """查询引擎——从 ontology_store.db 中提取聚合信息"""

    @staticmethod
    def daily_ranking(source: str = "douyin", date: str = None) -> list[dict]:
        """某数据源某日景区排名"""
        ...

    @staticmethod
    def trend(spot_id: str, metric: str, days: int = 7) -> list[dict]:
        """某景区某指标趋势"""
        ...

    @staticmethod
    def competitor_comparison(spot_id: str, days: int = 7) -> list[dict]:
        """某景区 vs 其竞品群的对比"""
        ...

    @staticmethod
    def weekly_insight() -> str:
        """本周核心洞察——跨源聚合"""
        ...

    @staticmethod
    def anomaly_detection(date: str = None) -> list[dict]:
        """检测异常波动（环比突变 > 20%）"""
        ...
```

### 4.3 自然语言查询（LLM Bridge）

```
用户问: "这周哪个竞品搜索涨得最快？"
         │
         ▼
Query Layer 翻译为:
1. ONTOLOGY: List[ScenicSpot] WHERE category = "competitor"
2. ONTOLOGY: MetricSnapshot GROUP BY spot MAX(date) WHERE source = "douyin" AND metric = "search_index"
3. SORT BY daily_change DESC LIMIT 3
         │
         ▼
SQL: SELECT s.name, ms.value, ms.daily_change
     FROM metric_snapshots ms JOIN scenic_spots s
     WHERE ms.source='douyin' AND ms.metric_type='search_index'
       AND ms.date = (SELECT MAX(date) FROM metric_snapshots WHERE source='douyin')
     ORDER BY ms.daily_change DESC LIMIT 3
         │
         ▼
结果: "只有河南（+12.3%）、清园（+8.1%）、万岁山（+5.4%）"
```

## 五、Action Layer：Actions 标准化

### 5.1 当前状态 vs 目标

```
当前: Python 脚本直接调 send_feishu_card.py → 飞书群
目标: Report/Layer → Action Request → Action Handler → 飞书群
                                     ↓
                               Action Log (审计)
```

### 5.2 Action 注册表

```python
ACTION_REGISTRY = {
    "send_card": {
        "handler": "actions/send_card.py",       # 封装 send_feishu_card.py
        "params": ["channel", "card_json"],
        "audit": True,
    },
    "create_alert": {
        "handler": "actions/create_alert.py",     # 异常提醒
        "params": ["severity", "title", "detail", "target_group"],
        "audit": True,
    },
    "update_ontology": {
        "handler": "actions/update_ontology.py",  # 写入 Ontology Store
        "params": ["object_type", "object_id", "data"],
        "audit": True,
    },
}
```

### 5.3 Action 标准化过渡路径

```
Phase 1 (Now):   adapter 直接写 JSON 文件 + send_feishu_card.py 直接发
Phase 2 (本周):   adapter → SQLite 写入 ← 先做这个
Phase 3 (下周):   report 通过 OntologyQuery 获取数据 → Action Handler → 发送
Phase 4 (2周后):   所有 cron 输出都通过 Action Layer
```

## 九、如何验证接入成功

### 验证清单

```
[ ] ontology_store.py 能 CREATE TABLE 所有表
[ ] adapter-douyin.py 写完 SQLite 后，SELECT 返回正确行数
[ ] adapter-xiaohongshu.py 写完 SQLite 后，content_assets 表有记录
[ ] ontology_query.daily_ranking() 返回格式正确的结果

[ ] .gitignore 排除 .profile/ontology/
[ ] 飞书卡片报告仍能正常发送
```

### 回滚方案

如果 SQLite 接入出现问题：
1. 停掉写入逻辑（adapter 只写 JSON，不写 SQLite）
2. 报告回退到旧模式（直读 JSON）
3. 排查问题后再开启

> 📌 结论：SQLite + 双轨策略 = 最少侵入、最大收益的本地接入方案。
> 从今天起 adapter 同时写 JSON（备份）+ SQLite（查询），观察两天后逐步切换。
