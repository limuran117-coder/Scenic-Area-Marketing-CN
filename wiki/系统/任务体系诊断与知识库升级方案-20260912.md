## 三、真问题（事实 + 证据）

### P0-1 索引层被流水淹没（最大成本项）
- `行业知识/结论索引.md`：255,775 字符；月度分布 5月8 / 6月741 / 7月402 / 8月452 / 9月197
- 日报类任务逐条追加：抖音指数日报 400 次、竞品内容动态 326、舆情监控 242、竞品爆款拆解 176
- **13 个任务 prompt 含"前置必读结论索引"** → 每次运行读取 255K tokens
- karpathy 标准（wiki/index.md）应为"目录 + 一句话 + 链接"，当前仅 30,295 字符

### P0-2 沉淀契约混乱
| 写法 | 任务 | 问题 |
|------|------|------|
| 追加主索引 | 抖音指数日报、竞品内容动态、舆情监控 | 与 P0-1 同因 |
| 写子文件 | 竞品关键词（`结论索引/已验证结论_竞品关键词深度分析.md`） | 与主文件口径不一，两处都需读 |
| 写案例库 | 案例库更新、文旅营销案例、爆款公式库 | 规范（保持）|
| 写 `/tmp` | 每日复盘整合-内容生成（`/tmp/daily_recap_*.json`） | **易失**，重启/清理即丢 |
| **写已删除的文件** | **周度技能探索**（写 `workspace/TOOLS.md`）| **实测该文件 2026-09-06 已删除并迁入 AGENTS.md，任务仍在写、仍报 done → 静默失败** |
| 无沉淀 | 8 个技术运维任务 | 运行经验（踩坑/有效模式）无处落 |

### P0-2b 沉淀「零校验」：执行完成 ≠ 经验已沉淀（2026-09-12 实证）
- **周度技能探索**：写 `workspace/TOOLS.md`，该文件 2026-09-06 已删除（内容迁入 `AGENTS.md:158 Local notes (migrated from TOOLS.md)`）。实测 workspace 根下无 TOOLS.md，任务却照常报 done（`/tmp/.skill_explore_20260912` 标记存在）→ **连续多周沉淀落空且无人发现**
- 同类：`Graphiti-Ontology同步` 依赖 `export DEEPSEEK_API_KEY=$(cat /tmp/ds_key.txt)`，**实测 /tmp/ds_key.txt 不存在** → 周任务随时会因 /tmp 被清而静默失败
- 系统对「沉淀成功」**无任何断言**（无 `test -s <目标>` / mtime 校验）→ 「执行完成」与「经验入库」脱钩，这是站长诉求最直接的落空点

### P1-3b 治理闭环断裂（cron_governor 实证）
- `cron_governor.py` 的自动优化项生成条件过窄（仅「timeout 未设或 <900 且 kind=agentTurn」）
- 实测 9/12 同一份报告同时含：`建议提高 timeout 120→1500`（CDP Cookie同步）与 `自动优化建议 0 项`
- 即：**检测到了 → 给了建议 → 但进不了自动应用清单**；且 `--apply` 后无 verify 步骤，「检测→改进→验证」三段各缺一环

### P1-3c 「任务失败 → 数据链断裂」实证
- 9/12 00:30 健康检查：**小红书 cookie 40.42h 未更新**（fresh=false，mtime 9/10 08:05）、抖音 cookie 17.49h 未更新
- 根因：CDP Cookie同步任务连续多日超时失败 → cookie 文件不刷新 → **下游采集任务一直在用陈旧 cookie**
- 今日修复 cookie_hub 后已恢复（09:38 同步出 393 条）

### P1-3 缺"归并—去重—重建索引"环节
- 各任务各自 `exec echo >>` 追加（6/22 起禁 edit 大文件）→ 只能追加不能整理
- 无任何任务负责：合并重复结论、淘汰过期条目、重建索引、标记矛盾

| karpathy 层 | 最新更新 | 状态 | 谁在写 |
|----|---------|------|--------|

| `sources/` | 08-22 | 停滞 | 无 cron |
| `concepts/` | 07-23（概念页全 06-30） | 冻结 51 天 | **无 cron 认领** |
| `entities/` | 08-13（竞品实体全 06-30） | 冻结 | 无 |
| `queries/` | 06-30 | 冻结 73 天（QUERY 从未 job 化） | 无 |
| `index.md` | 08-13（30 天） | 停滞（页头日期自相矛盾） | 无 |

**全库 383 个文件（md+json）新鲜度实测：7 天内 14 个(3%)、60 天以上 241 个(62%)** —— 知识库"越跑越散"，不是"越用越厚"。

### P1-4b 索引分裂：一批结论"物理不可发现"
- 嵌套文件 `行业知识/结论索引/结论索引.md`（11 行）独有 7/1 与 8/6 两批结论

### P1-4c 矛盾只标注不裁决
- 主文件内 283 处「矛盾」、22 处「修正」，**无任何机制裁决/退休**

## 四、升级方案（5 项，按优先级）

### 方案 A（P0）结论索引分层瘦身
- **做什么**：`结论索引.md` 瘦身为**索引层**（≤10KB：分主题目录 + 一句话 + 链接）；正文按月/按任务拆到 `结论索引/<任务>_<YYYY-MM>.md`
- **任务侧改动**：13 个任务不再"读主文件"，改为"读索引 + 按需读本文子文件"
- **收益**：单次读取 255K → ~5K tokens；检索从"全文扫描"变"按目录定位"
- **风险**：低（内容不删，只搬移 + 建索引），需一次性迁移脚本 + 备份

### 方案 B（P0）统一"沉淀契约"
每个 agentTurn 任务的 prompt 末尾强制声明沉淀目标，4 类产物各归其位：
| 产物类型 | 写入位置 | 格式 |
|---------|---------|------|
| 结论/洞察 | `结论索引/<任务>_<YYYY-MM>.md`（追加）| 表格行：结论/置信度/来源/日期/状态 |
| 案例 | `全国景区案例库/<案例名>-<周次>.md`（已有规范）| 保持 |
| 经验/教训 | `系统/任务经验库.md`（新建，追加）| 任务名 / 现象 / 根因 / 处置 |
| 数据快照 | `sources/<数据名>.md` | 保持 |

### 方案 C（P1）新增"知识归并"周任务
- 独立 cron（建议周日 09:30，紧随周日洞察汇总）：扫描本周各任务产出 → 合并重复结论 → 标记矛盾 → 重建 `结论索引.md` 索引层 → 更新 `index.md`/`overview.md`/`log.md`
- **价值**：把"沉淀"从各任务自行追加，升级为**集中治理**；即使某任务失败，归并环节仍能从残留产物回收知识（解 W29 断档）

### 方案 D（P1）经验沉淀通道
- 新建 `wiki/系统/任务经验库.md`：每个运维/治理任务把"本周踩坑 + 有效模式"追加一行
- 已有基础：cron自进化-每周治理（治理闭环）、周度技能探索（工具评估）——扩展为统一经验层

### 方案 E（P2）知识库健康检查扩展
- 现 `代码库Wiki漂移检查` 只查代码/文档漂移
- 扩展检查项：结论索引完整性（索引↔子文件一致）、停滞目录告警（>30 天未更新）、`raw/` 未消化文件、孤儿页
