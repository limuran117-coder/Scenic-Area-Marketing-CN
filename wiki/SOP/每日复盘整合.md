# 每日复盘整合 SOP

> 每日22:00汇总复盘 | 时间已调整（原17:00）

## 常见错误（Common Rationalizations）

| 常见的想法 | 事实 |
|:---------|:-----|
| "今天没出什么问题，随便写写" | ❌ 复盘的价值在平常日子：记录正常值=异常时才有对比基线 |
| "抖音数据没采到，先空着" | ❌ 缺失本身就是重大信号，必须写入问题部分 |
| "昨天已经说过这个问题了" | ❌ 问题没解决就得天天写，直到解决为止 |
| "数据多写几条显得有工作量" | ❌ 宁缺毋滥，3条精准>10条凑数 |

## 红色警报（Red Flags）

- 🔴 当日有任务执行失败但未在复盘中提及 → 复盘失职
- 🔴 连续3天重复同一问题未解决 → 需升级处理
- 🔴 复盘内容空泛无具体数据 → 质量不合格
- 🔴 未读取cron状态文件确认各任务执行情况 → 复盘不可信
- 🔴 客流CSV当日未更新但未提及 → 数据链条断裂

## 输出检查（Verification）

发送前确认：
- [ ] 已读取cron jobs-state.json确认每个任务的执行状态
- [ ] 已读取各isolated session日志确认是否成功发送
- [ ] 今日失败/异常任务已标注原因
- [ ] 关键数字已有环比对比（非孤立数据点）
- [ ] 判断层包含3项（今日最大发现/明日最该做1件事/风险点）
- [ ] 学习闭环已运行（触发规则？验证结果？）
- [ ] 所有显式提及的日期/数据已标注

## 汇总内容（必须包含4个部分）

1. **今日各任务执行情况**：成功/失败/异常
2. **关键数据发现**：抖音指数/竞品动态/行业热点中的重要信号
3. **潜在问题**：数据缺失/平台异常/执行遗漏
4. **次日改进建议**
