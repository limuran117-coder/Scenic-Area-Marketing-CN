## 📋 #2 复盘 cron 拆分（已完成）

### 核心变更
- 原「每日复盘整合」（22:00，一把梭）→ 拆为两步
- 22:00「每日复盘整合-内容生成」：只生成 `/tmp/daily_recap_<日期>.json`
- 22:05「每日复盘整合-投递」：读 JSON → 投递飞书群
- 新增 `scripts/daily_recap_deliver.py`（4.6KB）

### 失败模式对比
| 场景 | 旧行为 | 新行为 |
|---|---|---|
| 内容生成 + 投递都成功 | ✅ exit 0 | ✅ exit 0 |
| 内容生成失败 | ❌ exit 1（无 JSON） | ❌ exit 1（无 JSON） |
| 生成 OK + 投递失败 | ❌ exit 1（**数据丢失**） | ⚠️ exit 1（**JSON 仍在 /tmp**，私聊告警） |
| 投递偶发超时 | ❌ 整次失败 | ⚠️ cron 自身重试 4 次（22:05/10/15/20） |

### 关键设计
- 内容生成 prompt **禁用 send_feishu_card.py**——避免和投递阶段混淆
- 投递脚本带 `--no-retry`（cron 自身每 5min 重试更稳定）
- 投递失败 → 自动私聊推告警（不再沉默）
