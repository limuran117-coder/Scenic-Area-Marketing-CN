# 决策推敲流程（GStack Office-Hours × 运营适配版）

> 借鉴 Garry Tan GStack /office-hours 的六大力推敲问题方法论，用于优化决策规则库的每条规则质量。

---

## 核心原则

**推敲不是质疑，是检验。** 每条规则在验证前至少通过6个维度的压力测试，避免"听起来对但经不起推敲"的伪规则。

**不确定性可视化。** 每条规则附带置信度评分（1-10）和反例列表。

---

## 六大推敲问题（适配运营版）

### Q1：需求真实性 — "这件事真的在发生吗？"

**原始数据 → 现象确认**

| 问题 | 说明 | 反面教材 |
|------|------|---------|
| 触发条件的原始数据来自哪里？ | 抖音指数 / 客流CSV / 小红书搜索 / 微博热搜 | "我注意到搜索在下降"→没有数据来源 |
| 趋势持续了多久？ | 单点还是趋势？ | "今天搜索跌了"→可能是噪音 |
| 跨平台交叉验证了吗？ | 抖音跌了，小红书涨了吗？ | 只看抖音不看小红书 |

**推敲产出：** `🟢现象确认` / `🟡信号弱，需继续观察` / `🔴噪声，忽略`

---

### Q2：现状基线 — "没有这个规则时会怎样？"

**当前做法 → 成本量化**

| 问题 | 说明 | 反面教材 |
|------|------|---------|
| 目前靠什么决策？ | 经验/直觉/上级指示/数据 | "没有什么规则，完全凭感觉" |
| 这个做法的成本是什么？ | 时间/人力/机会成本 | "反正也没人在意"→低估隐性成本 |
| 曾经错过什么？ | 因缺少规则导致的损失案例 | "从来没细想过错过什么" |

**推敲产出：** 现状成本估算（量化或定性） + `🟢值得建规则` / `🟡优先级不高`

---

### Q3：具体性压力 — "规则里的关键词真的定义清楚了吗？"

**模糊术语 → 精确操作定义**

检查规则文本中被模糊的术语：

| 模糊词 | 常见滥用 | 需要精确定义为 |
|--------|---------|--------------|
| "异常波动" | 任何变动都被归为异常 | 周环比>30% 或 连续3日趋势 |
| "下降趋势" | 2天下降就说趋势 | 连续5天下降且累计>15% |
| "关注" | 无法操作的模糊动词 | 输出明确动作：XX指标→触发YY动作 |
| "跟进" | 不知道跟什么进 | 产出XX格式报告 / 调取XX数据 / 发送XX预警 |

**推敲产出：** 规则文本中的每个模糊术语被替换为可量化/可执行的定义

---

### Q4：最小生效边界 — "这条规则的最小有效版本是什么？"

**理想规则 → 可执行规则**

| 问题 | 说明 | 反面教材 |
|------|------|---------|
| 规则需要多少数据才能触发？ | 是否能立即落地 | "需要比较去年同期的客流"→没有数据 |
| 触发后最小动作是什么？ | 不是整个方案，是第一步 | "制定完整应对方案"→太模糊 |
| 这条规则能不能不加人工判断？ | AI能否自动执行 | "结合经验判断"→没有规则价值 |

**推敲产出：** 规则的`最小可行触发条件` + `第一步动作`（可自动化执行）

---

### Q5：反例检验 — "什么情况下这条规则会出错？"

**假设验证 → 边界发现**

| 问题 | 说明 | 反面教材 |
|------|------|---------|
| 到什么点时这条规则不适用？ | 反例列表 | "所有情况都适用"→没有边界意识 |
| 被误触发的代价是什么？ | 假阳性成本 | "反正提醒了也不亏"→可能产生警报疲劳 |
| 上次这条规则判断错误是什么？ | 历史验证 | "还没验证过"→规则还不够成熟 |

**推敲产出：** 规则边界条件列表 + 假阳性风险评估

---

### Q6：未来适配性 — "3个月后这条规则还成立吗？"

**当前规则 → 抗衰减设计**

| 问题 | 说明 | 反面教材 |
|------|------|---------|
| 依赖的环境因素会变吗？ | 季节/政策/竞争格局 | "五一之后搜索规律还一样吗"→季节性假设 |
| 竞品策略变化会打破假设吗？ | 竞品变化后的规则失效 | "清园杨洋过后还适用吗"→单事件驱动 |
| 数据源变化后怎么办？ | TikTok替代/平台改版 | "依赖的指标停更了怎么办"→无B计划 |

**推敲产出：** 规则有效期的预估 + 失效条件 + 替代数据源

## 流程：规则推敲会议

### 谁参加
- 规则提出者（输出）
- 反方推敲者（挑战，建议使用AI）
- 决策记录者（记录推敲结果）

### 步骤

**Step 1：规则草稿**（提出者）—— 写出规则初稿
```
触发条件: [数据源+阈值]
判断逻辑: [决策树]
建议动作: [可执行输出]
```

**Step 2：六轮推敲**（反方推敲）—— 每轮一个问题，逐一回答

输出格式（每次推敲后）：
```
Q1 需求真实性
  ✅ 回答: [回答内容]
  🟢/🟡/🔴 状态
  迭代建议: [如需要]
```

**Step 3：规则定稿**

推敲后的规则格式：
```
### RXX 规则名
- **触发条件**：[精确可量化条件]
- **判断逻辑**：[决策树，含分支]
- **建议动作**：[可执行的最小动作]
- **反例列表**：[推敲Q5产出]
- **预估有效期**：[推敲Q6产出]
- **置信度**：[1-10，通过推敲后默认≥7]
- **验证状态**：🟡待验证（新规则默认状态）
```

---

## 与决策规则库的衔接

每条现有规则需通过六轮推敲重新审核，输出：

| 规则 | 当前状态 | 推敲后调整 | 置信度调整 |
|:----:|:-------:|-----------|:---------:|
| R01 | 🟢已验证 | — | 维持 |
| R02 | 🟢已验证 | 补充最小动作定义 | 提升 |
| R08 | 🟢已验证 | 补充执行保障机制（源自Q4） | 提升 |
| 新规则 | 🟡待验证 | 推敲后首次发布 | 默认≥7 |
