# 防错机制 SOP（2026-06-16 制定）

> **背景**：今日（6/16）周度客流洞察任务连续暴露三类错误：
> 1. 逻辑错误：端午日期搞错（CSV header 写"6月3日·端午"误以为是端午正日，实际是6/19）
> 2. 数据错误：CSV 6/8-6/15为0未确认就误用
> 3. 工程错误：Python heredoc 长脚本引号/括号嵌套问题
>
> **目的**：建立系统化防错机制，防止同类错误重复发生。

---

## 1. 防错机制三大原则

| 原则 | 含义 | 解决什么问题 |
|---|---|---|
| **A. 单一事实源（SSOT）** | 每个关键事实只在一个地方写明，其他地方引用 | 防止端午日期在不同地方有不同版本 |
| **B. 写入前验证** | 任何"事实"在写入 MEMORY/报告/卡片前必须核实 | 防止错误数据被固化为"标准" |
| **C. 执行前检查清单** | 长任务/脚本执行前强制走 5 步检查 | 防止工程错误和逻辑错误 |

---

## 2. 单一事实源（SSOT）建设

### 2.1 节假日 SSOT

**问题**：今日端午日期混乱（CSV header 6/3、MEMORY 旧记录 6/3、MEMORY 修正 6/19 互相冲突）

**解决**：所有节假日日期只在一个地方维护：`wiki/行业知识/节假日基准.md`

| 节日 | 2026日期 | 星期 | 调休安排 |
|------|----------|------|----------|
| 元旦 | 1/1 | 周四 | 1/1-3 放假 |
| 春节 | 2/17-23 | — | 2/13-2/17调休 |
| 清明 | 4/4-6 | — | 4/4-6 放假 |
| 五一 | 5/1-5 | — | 5/1-5 放假 |
| **端午** | **6/19-21** | **周五-周日** | **6/19 放假，6/20-21 周末** |
| 中秋 | 9/25-27 | — | 9/25-27 放假 |
| 国庆 | 10/1-7 | — | 10/1-7 放假 |

**强制规则**：
- ❌ **禁止**在 MEMORY.md、CSV 备注、个人判断里再写节日日期
- ✅ 引用统一从 `wiki/行业知识/节假日基准.md` 读
- ✅ 任何节日相关分析任务，前置步骤必须读这个文件

### 2.2 数据源 SSOT

**问题**：今日 6/8-6/15 数据 CSV=0，xlsx 有数据，不知道用哪个

**解决**：

| 数据类型 | 权威源 | 备份源 | 同步规则 |
|---|---|---|---|
| 历年客流（2023-2025）| `~/Desktop/2023-2025年门票销售及客流统计数据表.xlsx` | — | 唯一权威源 |
| 2026年每日客流 | `~/Desktop/2026游客量统计.csv` | `~/Downloads/2026游客量统计*.xlsx` | CSV 是主源；CSV 没数据时查询 xlsx 备份 |
| 2026年单日详情 | `~/Downloads/2026游客量统计*.xlsx` | — | xlsx 是单日详情唯一源 |

**强制规则**：
- 数据有冲突时（CSV vs xlsx），**xlsx 优先**（数据更完整）
- 读不到数据 → 报告"数据缺失" → **不编造** → 不静默跳过

### 2.3 结论 SSOT

**问题**：今日端午评估混乱，结论互相矛盾

**解决**：
- 所有洞察结论写入 `wiki/行业知识/结论索引.md`
- 矛盾结论必须显式标注（"⚠️ 与 YYYY-MM-DD 结论矛盾"）
- **不静默覆盖**旧结论

## 3. 写入前验证（铁律）

### 3.1 MEMORY.md 写入前必检

每次写入 MEMORY.md 前，强制执行 3 步验证：

```
[ ] 第一步：搜索是否已存在
   - memory_search 查询关键词
   - 如果存在 → 对比是否矛盾 → 显式标注而非覆盖
[ ] 第二步：交叉验证
   - 数据有数字 → 跑一次实际查询确认数字正确
   - 日期有节日 → 读 wiki/行业知识/节假日基准.md 确认
[ ] 第三步：标注来源
   - 每个 entry 必须标 source（来自哪份文件/对话/截图）
   - 标 [user]/[feedback]/[project]/[reference] 类型
```

### 3.2 飞书卡片/报告发送前必检

```
[ ] 数据已用代码验证（不是凭印象）
[ ] 节日/日期已对照 SSOT
[ ] 至少 1 个同行/竞品数据维度（不做单点判断）
[ ] 异常数据已标注（如 6/8 收入异常）
[ ] 不确定的地方写"数据缺失"而非"约"
```

### 3.3 cron prompt 修改前必检

```
[ ] 读现有 prompt 全文（不基于记忆）
[ ] 在测试/干环境手动跑一次确认
[ ] 修改后保留 1 周观察期
```

## 4. 执行前检查清单（任务5步法）

### 4.1 长任务（>5分钟或含脚本执行）必须走 5 步

```
Step 1 数据源确认（30秒）
  - 列出本次任务需要的所有数据源
  - 每个数据源检查"是否存在 + 最新到何时"
  - 缺失数据 → 记录到"数据缺失清单"

Step 2 关键事实核实（1分钟）
  - 日期/节日 → 读 wiki/行业知识/节假日基准.md
  - 历史结论 → 读 wiki/行业知识/结论索引.md
  - 关联事件 → 读 memory/YYYY-MM-DD.md（最近3天）

Step 3 脚本编写（heredoc > 30 行 → 改用 write 文件）
  - < 30 行的临时脚本：exec + heredoc
  - ≥ 30 行的脚本：write 写到 /tmp/tmp_script.py，python3 执行，执行后删除
  - 多行 f-string → 用 + 号拼接，不用 \n 转义
  - 字符串里出现 " 或 ' → 用 """...""" 三引号包裹

Step 4 发送前最后检查
  - 数据是真实读取的（不是估算）
  - 图表不是乱码（PNG 完整性）
  - 卡片数量 ≤ 5（飞书表格上限）
  - 表格数 > 5 张时拆卡片

Step 5 发送后验证
  - 检查飞书群消息是否到达
  - 检查卡片渲染是否正常
  - 异常立即修复并重新发送
```

### 4.2 工程错误防范（heredoc → write 文件）

**问题**：今日多次 Python heredoc 因引号/括号嵌套问题失败，浪费 30+ 分钟

**强制规则**：
- 临时一次性脚本（< 30 行）：可以 exec + heredoc
- 任何复用脚本 / > 30 行 / 含复杂字符串：用 `write` 工具写文件，再用 `exec` 调用
- 含中文/特殊字符的字符串：用 `+` 拼接或 `chr()` 转换
- 包含反斜杠的：禁用，改用 raw string 或预定义变量

### 4.3 错误模式库（今日新增）

| 错误模式 | 触发条件 | 防范措施 |
|---|---|---|
| 节日日期搞错 | CSV header 出现"端午"等字样 | 一律以 wiki SSOT 为准 |
| 误用未同步数据 | CSV 6/8-15=0 但任务用 18:00 之前数据 | 数据源确认步骤检查"最新到何时" |
| heredoc 嵌套引号 | exec + Python 多行 f-string | 改用 write 工具 |
| 5h 模型限额 | 用 M3 时撞限 | 默认 M2.7，关键任务用 M3 |
| 飞书表格超限 | 单卡 > 5 个表格 | 拆 4-5 张卡 |
| 卡片内容超字节 | 表格内含长字符串 | 列宽控制或拆行 |

## 5. 自我检查触发器（自动化）

### 5.1 每周自我审计

**时机**：每周日 9:00（系统升级 cron 之前）

**内容**：
- 本周所有交付的卡片/报告 → 是否有错误被反馈
- 本周所有写入的 MEMORY → 是否与 SSOT 矛盾
- 本周所有执行的脚本 → 是否有重复失败模式

### 5.2 每月准确率统计

**指标**：
- 卡片发送成功率（无乱码/无错误数据）
- 结论准确率（与实际验证的一致性）
- 任务按时完成率

### 5.3 异常自动告警

| 异常 | 自动告警触发 |
|---|---|
| CSV 数据空值率 > 30% | 发飞书"数据源异常" |
| 节日日期与 SSOT 不一致 | 自动暂停 + 显式询问 |
| heredoc 失败 3 次 | 自动改用 write 文件 |
| 卡片发送失败 2 次 | 暂停并报告 |
